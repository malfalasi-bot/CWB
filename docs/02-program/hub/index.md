## Conventions for staying organised

Six rules keep the project readable as it grows past one module; the hub is the only place status and decisions change, and every other document is either a live reference with a version or a dated record that is never edited.

1. **One hub.** Status, decisions and open questions live here and nowhere else; other documents point to this one for state.
2. **One register.** Units exist in the Master Structure only; a module's redesign is merged into it with a mapping and a version, and the pass record that proposed it is not edited afterwards.
3. **One framework.** Rules and principles live in Final Structure, by version; a rule quoted elsewhere is a pointer, not a copy.
4. **One module file per module.** F1's file is §7 of this hub until it outgrows it; when it does, it becomes its own document with the same sections (versions, registers, research status, next actions), and this hub keeps a one-line status.
5. **Pass records are dated and frozen.** "F1 Pass 2 v1" and "v2" are records of what was found and proposed; corrections go into the module file and the register, with a note of what superseded what.
6. **Versions and names.** Structure versions are v3.x; a module's unit list carries its own version (F1 v3.3); pass records are numbered per module (Pass 2 v1, v2); registers are named by content (world-set register, claims register, asset register); new units take letters until a module is renumbered through the factory, when the mapping is recorded.

**Seventh rule, added at your request on 2026-09-28: questions always appear in the chat.** Every reply that leaves anything for you to decide lists every open question in the chat itself, numbered, with the recommendation, whatever the documents also say. The documents keep the detail; the chat keeps the list.

**Working rhythm from here.** Each of your working days: read the hub's status and questions first; answer or comment; I update the hub, run the next action, and leave the new state here. Each of my working sessions ends by updating §4 and §7 of this hub.
