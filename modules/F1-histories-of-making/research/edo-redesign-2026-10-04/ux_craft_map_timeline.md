## KQ1 — What exact patterns do the top scrollytelling templates use for the text/instrument split and for mobile?

### Takeaway
The de-facto standard is a `position: fixed/sticky` instrument filling the viewport with a narrow scrolling text column (Mapbox template: 33vw column with a 5vw gutter, or a 50vw centred card; 90vw full-width cards under 750px), driven by Scrollama step triggers at a 0.5 viewport offset. On mobile the two reputable choices are "keep it scrolly" (instrument pinned, text cards overlaid at ~90vw) or "stack" (one static graphic per step); never use `vh` for step heights, use px from `window.innerHeight`, and switch Scrollama offsets to pixels.

### Cited Findings

**Mapbox Storytelling template (BSD-3-Clause, mapbox/storytelling, 673 stars) — exact CSS and config values**
- Chapter `alignment` options are `center`, `left`, `right`, `full`; "Defaults to `center` for browser windows less than 750 pixels wide." — [Mapbox storytelling README](https://github.com/mapbox/storytelling)
- The template's index.html defines: `#map {height:100vh; width:100vw; position:fixed}`; `.centered {width:50vw; margin:0 auto}`; `.lefty {width:33vw; margin-left:5vw}`; `.righty {width:33vw; margin-left:62vw}`; `.fully {width:100%}`; `.step {padding-bottom:50vh; opacity:0.25}`; `.step.active {opacity:0.9}`; `.step div {padding:25px 50px; line-height:25px; font-size:13px}`; `@media (max-width:750px)` all alignments become `width:90vw; margin:0 auto`; light theme `#444` on `#fafafa`, dark theme inverted. — [mapbox/storytelling index.html](https://raw.githubusercontent.com/mapbox/storytelling/main/index.html)
- Scrollama is set up with `step: '.step', offset: 0.5, progress: true`; map is created with `interactive: false`; `mapAnimation` defaults to `flyTo` (options `flyTo`, `easeTo`, `jumpTo`); layer opacity is faded per chapter via `onChapterEnter/onChapterExit` with optional `duration` applied through `*-opacity-transition`. — [index.html](https://raw.githubusercontent.com/mapbox/storytelling/main/index.html); [README](https://github.com/mapbox/storytelling)
- `rotateAnimation`: README says it "Rotates 90 degrees over 24 seconds", but the shipped index.html calls `map.rotateTo(bearing + 180, {duration: 30000, easing: t => t})` (180° over 30 s, linear). Discrepancy between docs and code. — [README](https://github.com/mapbox/storytelling); [index.html](https://raw.githubusercontent.com/mapbox/storytelling/main/index.html)
- With `use3dTerrain`, the template uses `setTerrain({exaggeration: 1.5})` plus a sky layer. — [index.html](https://raw.githubusercontent.com/mapbox/storytelling/main/index.html)
- Template adds a mobile fix: `touch-action: unset` on the canvas container to stop scroll breaking. — [index.html](https://raw.githubusercontent.com/mapbox/storytelling/main/index.html)
- Layer prep rule: style custom layers with opacity 0 (not hidden) so the template can fade them in. — [README](https://github.com/mapbox/storytelling)
- The Mapbox GL "scroll fly-to" example uses per-chapter camera options including `duration: 6000` and `speed: 0.6`. — [Mapbox example](https://docs.mapbox.com/mapbox-gl-js/example/scroll-fly-to)

**MapLibre ports of the template (zero-cost)**
- `opengeos/maplibre-gl-storymaps` reproduces the same chapter schema (`alignment` left/right/center/full, `hidden`, `mapAnimation` flyTo/easeTo/jumpTo, `rotateAnimation`, `onChapterEnter` with `duration: 3000` example, `location.speed: 0.5`, `curve: 1`) on MapLibre with free CartoCDN styles. — [opengeos/maplibre-gl-storymaps](https://github.com/opengeos/maplibre-gl-storymaps)

**The Pudding — responsive scrollytelling rules (Russell Samora, Apr 2017; sticky post Jun 2018)**
- Two legitimate mobile strategies: keep it scrolly (preserve transitions when they carry meaning, e.g. "change over time or spatial movement") or stack static charts (better when performance suffers, steps stand alone, or a different chart type is needed on mobile). Steppers and swipe/tap are explicitly not recommended. — [Pudding, Responsive scrollytelling](https://pudding.cool/process/responsive-scrollytelling)
- "don't use vh for scrollytelling" because mobile browser chrome resizes the viewport; set step heights in px from `window.innerHeight` on load/resize. — [Pudding](https://pudding.cool/process/responsive-scrollytelling)
- Keep CSS and JS breakpoints in sync via `window.matchMedia('(min-width: 800px)')`; add an `is-mobile` class to `<html>` for device-specific CSS. — [Pudding](https://pudding.cool/process/responsive-scrollytelling)
- Remove hover interactions on mobile and replace with fixed annotation text; keep pacing short. — [Pudding](https://pudding.cool/process/responsive-scrollytelling)
- Sticky-graphic pattern: offload the "stuck" state to CSS `position: sticky` (relative to the parent's bounds, so overlap of multiple stuck elements is controllable); two canonical layouts demonstrated: side-by-side and text overlay; graceful degradation if unsupported. — [Pudding, Easier scrollytelling with position sticky](https://pudding.cool/process/scrollytelling-sticky)
- Scrollama (MIT) ships examples "Sticky Graphic (Side by Side)" and "Sticky Graphic (Overlay)" and a Custom Offset per step via data attribute. — [russellsamora/scrollama](https://github.com/russellsamora/scrollama)
- Scrollama README (as summarised by a practitioner reference) deprecated its own container callbacks as of 2.0.0 in favour of CSS `position: sticky`, and ships a "mobile pattern" example using pixel offsets so triggers don't jump on scroll-direction change. — [scrollytelling.ai design patterns](https://scrollytelling.ai/scrollytelling-design-patterns) (secondary source quoting the scrollama README)

**Pattern vocabulary and mobile/reduced-motion fallbacks (practitioner reference, 2026)**
- Named patterns: sticky figure (side-by-side vs overlay; overlay "more cinematic" but risks unreadable text over busy imagery), scrubbed sequence, step triggers, staged reveal; recommended fallbacks: stack figure above each step; show 3–5 key frames as stills; fire triggers instantly; render final state immediately. The stacked layout "is also the correct `prefers-reduced-motion` layout". — [scrollytelling.ai](https://scrollytelling.ai/scrollytelling-design-patterns)

### Inferences
- For the Edo unit's two instruments (world map + timeline + city map), a single pinned "instrument stage" that swaps content per chapter (mirroring Mapbox's `hidden` chapters and layer fades) is more robust than two competing sticky regions; keep the text column at ~33vw/≤560px on desktop and go to 90vw overlay cards (or stacked stills) under ~750–800px.
- Because Mapbox's active/inactive card opacity is 0.9/0.25, readers get a clear "current step" cue without JS animation; this is a cheap pattern to copy.
- The Pudding's px-not-vh rule and Scrollama's pixel offsets on touch are the two most common causes of "janky" mobile scrollytelling; both are trivial to adopt.

### Gaps
- No NYT Open, Reuters Graphics or Guardian design-blog post with explicit pixel/percent values for their text/instrument split was found in this pass; the only hard numbers come from the Mapbox template and The Pudding. (Storybench's NYT Harriet Tubman interview describes process, not layout numbers.)
- Scrollama's exact mobile example code (pixel offset values) was not fetched directly; the claim is via a secondary source quoting the README.

## KQ2 — Best-practice numbers for fly-to durations, easing and arc animation, and for timeline event density

### Takeaway
MapLibre's `flyTo` defaults are `curve: 1.42` and `speed: 1.2` (Mapbox: `curve = 6^0.25 ≈ 1.565`, van Wijk 2003 "smooth and efficient zooming"); storytelling examples slow this to `speed 0.5–0.6` or fixed `duration` 6 000–12 000 ms, and both engines skip the flight entirely (jumpTo) under OS reduced-motion unless `essential: true`. Great-circle routes are drawn with turf.greatCircle (≈100 points) and animated over ~500 rAF steps or with `line-gradient`/`line-progress` (requires `lineMetrics: true`). For timelines, the best large-scale examples solve density by exponential/adaptive scale (Histography), uniform-disk layouts exploiting date uncertainty (Kräutli & Boyd Davis), and sampling a fixed number of thumbnails per span (Faces of Sweden: 7).

### Cited Findings

**Fly-to / camera**
- MapLibre `FlyToOptions`: `curve` default `1.42`; `speed` default `1.2` ("1.2 times options.curve screenfulls every second"); `screenSpeed` is screenfulls/sec with linear timing and is ignored if `speed` is set; `maxDuration` caps the animation in ms; `minZoom` sets the arc's outermost zoom. — [MapLibre FlyToOptions](https://maplibre.org/maplibre-gl-js/docs/API/type-aliases/FlyToOptions/)
- Mapbox GL `flyTo` default `curve` is `Math.pow(6, 0.25)`, described as the root-mean-squared average velocity per van Wijk (2003); a value of 1 produces circular motion; `easing` is a function 0..1→0..1; `essential: true` makes the animation ignore `prefers-reduced-motion`. — [Mapbox properties](https://docs.mapbox.com/mapbox-gl-js/api/properties)
- Mapbox `Map` option `respectPrefersReducedMotion` defaults to `true`. — [Mapbox Map](https://docs.mapbox.com/mapbox-gl-js/api/map)
- MapLibre `flyTo`: "The animation will be skipped, and this will behave equivalently to `jumpTo`" under OS reduced motion unless `essential: true`; same for `easeTo` (instant). — [MapLibre Map API](https://www.maplibre.org/maplibre-gl-js/docs/API/classes/Map)
- Mapbox "Slowly fly to a location" example uses `duration: 12000` with `essential: true`; the scroll-fly-to example uses `duration: 6000` and `speed: 0.6` on individual chapters. — [Mapbox flyto-options](https://docs.mapbox.com/mapbox-gl-js/example/flyto-options); [scroll-fly-to](https://docs.mapbox.com/mapbox-gl-js/example/scroll-fly-to)
- Mapbox storytelling template users add `essential: true` to a chapter's `location` to force animation regardless of reduced-motion preference (issue #62). — [mapbox/storytelling issue 62](https://github.com/mapbox/storytelling/issues/62)
- MapLibre exposes `setProjection(ProjectionSpecification)`, `setTerrain(TerrainSpecification)` ("Loads a 3D terrain mesh, based on a 'raster-dem' source"), `setSky`, `setRoll`, and `calculateCameraOptionsFromTo`. — [MapLibre Map API](https://www.maplibre.org/maplibre-gl-js/docs/API/classes/Map)
- A camera-rail pattern: keep a target route and a camera route separate, sample both with `turf.along(route, distance * progress)`, then `map.jumpTo(map.calculateCameraOptionsFromTo(cameraLngLat, altitudeMeters, targetLngLat))` each frame with `Easing.inOut(Easing.cubic)`; example altitude 180 000 m. — [Remotion maps docs (MapLibre)](https://www.remotion.dev/docs/maps)

**Great-circle arcs and animated routes**
- `turf.greatCircle(from, to, {npoints: 100})`; when the result is a MultiLineString (antimeridian crossing) take the longest segment; animate with `turf.lineSliceAlong(route, 0, routeDistance * progress)` and keep a minimum 0.001 km to avoid zero-length errors; for a visually straight line use a plain LineString instead. — [Remotion maps docs](https://www.remotion.dev/docs/maps)
- MapLibre "Animate a point along a route": arc built with `turf.along` over `steps = 500` ("more steps means a smoother arc… too many steps will result in a low frame rate"), one step per `requestAnimationFrame`, bearing from `turf.bearing`, icon layer with `icon-overlap: 'always'` and `icon-ignore-placement: true`. — [MapLibre example](https://maplibre.org/maplibre-gl-js/docs/examples/animate-a-point-along-a-route/)
- `line-gradient` works only on GeoJSON sources with `lineMetrics: true`, via an expression on `['line-progress']`. — [MapLibre gradient line example](https://maplibre.org/maplibre-gl-js/docs/examples/create-a-gradient-line-using-an-expression/)
- `ml-line-animation` (dependency-free, uses `line-gradient`) defaults: `dashLength 1`, `duration 1000` ms, `loop false`, head/tail colours interpolate via line-gradient. — [peterqliu/ml-line-animation](https://github.com/peterqliu/ml-line-animation)
- "Animate a line" example appends coordinates per frame with `speedFactor = 30` frames per degree and resets on `visibilitychange`. — [MapLibre animate-a-line](https://maplibre.org/maplibre-gl-js/docs/examples/animate-a-line/)
- d3 cuts geometry along the antimeridian at projection time, so arbitrary rotations work without artefacts; most shapefiles are pre-cut, which is why rotated aspects break in other software. — [Observable: Antimeridian cutting](https://observablehq.com/notebook-kit/ex/d3/antimeridian-cutting); [mbostock gist 3788999](https://gist.github.com/mbostock/3788999)

**Label collision / priority (MapLibre style spec)**
- `symbol-sort-key`: features with lower sort keys are drawn and placed first and get priority when `text-allow-overlap` is false; `text-allow-overlap` defaults to `false` (disabled by `text-overlap`); related controls `text-variable-anchor`, `text-variable-anchor-offset`, `text-radial-offset`, `text-padding`, `text-optional`, `text-ignore-placement`, `text-writing-mode` (vertical text is relevant for Japanese labels). — [MapLibre Style Spec: Layers](https://www.maplibre.org/maplibre-style-spec/layers)
- Glyphs: MapLibre GL JS ≥5.11.0 can omit the `glyphs` URL to use local fonts; otherwise SDF PBF glyph ranges of 256 code points are fetched per `{fontstack}/{range}` (relevant cost for kanji). — [MapLibre Style Spec: Glyphs](https://maplibre.org/maplibre-style-spec/glyphs)

**Timeline density and scale**
- Histography (Matan Stauber, Bezalel, 2015; ~15 000 Wikipedia events; WebGL via pixi.js) handles 14 billion years with an exponential slider: "the further you are in time, the shorter the steps" (e.g. 100-million-year steps at −3.7 Gyr, one-year steps at 1937); columns re-layout per selected range and dots fly to new positions with per-dot speed; an importance score 1–100 promotes events near the cursor. — [Smashing Magazine interview](https://www.smashingmagazine.com/2016/09/interview-with-matan-stauber/); [Communication Arts](https://www.commarts.com/project/23882/histography); [Adobe blog](https://blog.adobe.com/en/publish/2015/12/03/data-meets-design)
- Stauber abandoned 3D and nested-zoom timelines because "you had to zoom in a lot. It was too much effort"; the problem of proportion ("almost all historic events… happened in the last 500 years") is why timelines are usually period-bound. — [Adobe blog](https://blog.adobe.com/en/publish/2015/12/03/data-meets-design); [Communication Arts](https://www.commarts.com/project/23882/histography)
- User-testing critique of Histography: dots too small to scan; "more visually appealing than practical"; reads like a heat map rather than a comparable set of events. — [Timeline of Everything report](https://exa.ai/library/publication/4y8h0x7fqpy)
- British Museum × Google "Museum of the World" (2015, WebGL, built by Weir+Wong): a 3D-perspective timeline from ~2 Mya to present with five colour-coded regional tracks (Africa yellow, Americas orange, Asia green, Europe blue, Oceania purple), 319 objects (Africa 58, Asia 113, Europe 87, Americas 31, Oceania 30), five theme filters, jump menu and arrow keys; clicking a dot draws links to related dots and opens image/ID/audio/map. Critiques: no narrative framing; sparse prehistory gaps unexplained; 3D orientation makes temporal comparison hard; only one object viewable at a time. — [Internet Archaeology review](https://intarch.ac.uk/journal/issue44/13/index.html); [Timeline design for cultural heritage (thesis)](https://1library.net/document/yjv9d7my-timeline-design-for-visualising-cultural-heritage-data.html)
- Kräutli & Boyd Davis (EG UK CGVC 2015): represent each record as a same-size disk positioned by date, stacked vertically; exploit date granularity/uncertainty to spread records horizontally within their allowed span to reduce clutter; result reads like a histogram but keeps individual items inspectable; navigated with map-like zoom and pan. — [Kräutli & Boyd Davis PDF](https://researchonline.rca.ac.uk/1725/1/Kra%CC%88utli%20Boyd%20Davis%20-%20Revealing%20Cultural%20Collections%20Over%20Time%202015.pdf)
- Historical lineage: Priestley's 1765 Chart of Biography introduced the uniform-time-scale "mechanical" tradition; prior traditions were typographic lists and symbolic shapes (rivers, trees) that guide interpretation. — [Timeline design thesis](https://1library.net/document/yjv9d7my-timeline-design-for-visualising-cultural-heritage-data.html)
- Cleveland Museum of Art Gallery One uses timelines to contextualise curated items with period bands rather than to plot every item. — [Timeline design thesis](https://1library.net/document/yjv9d7my-timeline-design-for-visualising-cultural-heritage-data.html)
- "Faces of Sweden" (Swedish National Heritage Board prototype, 785 portraits 1570–2003): main density timeline drawn as translucent white rectangles per item date-span (more transparent for wider spans); two secondary timelines show up to 7 sampled thumbnails per selected span, sampled one per sub-span for even spread; images with precise dates positioned at that date; shuffle button for a new sample; bottom 8% of each image clipped via `clip-path: inset(0 0 8% 0)` to hide catalogue numbers; PhotoSwipe lightbox links to the full record. — [Faces of Sweden repo](https://github.laiyagushi.com/riksantikvarieambetet/Faces-of-Sweden)
- Horizontal timelines leave more room for detail and overlapping events; vertical works better on mobile but squeezes details; a student project placed the timeline in the bottom 25% of the screen with detail above. — [Timeline of Everything report](https://exa.ai/library/publication/4y8h0x7fqpy)
- Library status: TimelineJS3 is MPL-2.0 (commercial embedding allowed; modified source must be published); options include `scale_factor`, `zoom_sequence`, `initial_zoom`, `height`. — [TimelineJS licence page](https://github.com/NUKnightLab/TimelineJS3/blob/8dc59e54/website/templates/docs/license.html); [npm @knight-lab/timelinejs](https://www.npmjs.com/package/@knight-lab/timelinejs); [options](https://timeline.knightlab.com/docs/options.html). vis-timeline is "dual-licensed under Apache-2.0 and MIT". — [visjs/vis-timeline](https://github.com/visjs/vis-timeline/). ChronoZoom: "This project is retired and no longer supported, but is still available for use" (built on .NET). — [Microsoft Research](https://www.microsoft.com/en-us/research/project/chronozoom)

### Inferences
- Reasonable defaults for a chaptered Edo story: `flyTo` with `speed 0.6–0.8`, `curve 1.42`, `maxDuration ≈ 6000`; use `easeTo` (no zoom-out) for moves within the same city view and `jumpTo` when the context changes entirely (world → Edo city map), mirroring the three `mapAnimation` modes offered by the template.
- For the 1600–2024 timeline with a scale break, the Histography lesson is to make the scale break explicit and interactive (an exponential or piecewise scale with visible "fold" marks) rather than hiding it; the Kräutli approach (same-size markers, vertical stacking, spread within uncertainty) is the most defensible way to show ~50–200 dated events without clutter; Faces of Sweden's "7 thumbnails per span, resampled on demand" is a concrete density cap for thumbnails on a timeline.
- No source gives a numeric "events per 100 px" rule; the practical rule derived from the above is one thumbnail per ~120–160 px of track and a hard cap per visible span, with remaining events collapsed into density marks.

### Gaps
- No primary source on "folded"/scale-break timeline design was found (searched generally); the Met's Heilbrunn Timeline interface design and Information is Beautiful/Kurzgesagt timeline specs (type sizes, heights) were not located in this pass.
- MapLibre docs do not state `duration`/`easing`/`essential` defaults on the FlyToOptions page (they are inherited from AnimationOptions); defaults for `easing` were not confirmed.

## KQ3 — Step-by-step open-source workflow to georeference a historical map (Allmaps) and show it in MapLibre or Leaflet with pins and a transparency scrub

### Takeaway
Allmaps needs only a IIIF Image or Manifest URL: paste into editor.allmaps.org → optional mask → 4–6+ ground-control points → Export gives a Georeference Annotation URL (data auto-published CC0). Load that URL with `@allmaps/maplibre` (`WarpedMapLayer`, a MapLibre `CustomLayerInterface`; set `maxPitch: 0`) or `@allmaps/leaflet` (`L.Layer`; set `zoomAnimationThreshold: 1`), scrub opacity with `setOpacity(0–1)`, and add pins as ordinary GeoJSON/marker layers. For the Edo unit, IIIF-served candidates exist at Digital Commonwealth/Leventhal (1859 "Kaisei On'edo oezu", public domain, IIIF manifest), the Library of Congress (IIIF Image API at tile.loc.gov) and NDL Digital Collections (Edo kiriezu in IIIF; 保護期間満了 items free to use), and CODH has already extracted 7 918 place names from 29 Owariya kiriezu sheets.

### Cited Findings

**Allmaps pipeline**
- "All georeference data is saved automatically and published as open data under CC0." Start by pasting a IIIF URL. — [Allmaps Editor](https://editor.allmaps.org/)
- Georeference Annotations are W3C Web Annotations and an approved IIIF Presentation API extension; Allmaps "doesn't need to generate XYZ map tiles. All that's needed is a IIIF server." — [Allmaps](https://allmaps.org/); [@allmaps/annotation](https://allmaps.org/docs/packages/annotation)
- Editor steps (tutorial): find the IIIF manifest (David Rumsey: Share → IIIF Manifests; Stanford SearchWorks: sidebar → IIIF manifest), paste → Load; draw a mask and close it; click "Georeference"; add GCPs by clicking the real-world map then the historical map, "4-6 times" spread across the sheet. — [K. L. Larsen tutorial](https://kristinalivlarsen.com/blog/georeferencing-IIIF-to-leaflet-tutorial)
- Export: click the green Export button → open the Georeference annotation URL (pattern `https://annotations.allmaps.org/images/<id>` or `/manifests/<id>`); mask and transformation settings are stored in the annotation. — [UWM Allmaps workshop, Lesson 2](https://uwm-libraries.github.io/allmaps-intro-workshop/lessons/Allmaps)
- MapLibre plugin: `WarpedMapLayer` "extends MapLibre's CustomLayerInterface"; create `new WarpedMapLayer()`, `map.addLayer(warpedMapLayer)` on load, then `addGeoreferenceAnnotationByUrl(url)` or `addGeoreferenceAnnotation(json)`; note "does not support pitched maps. Disable pitch by setting maxPitch to 0". — [@allmaps/maplibre](https://allmaps.org/docs/packages/maplibre)
- Leaflet plugin: `WarpedMapLayer extends L.Layer`; set `zoomAnimationThreshold: 1` because multi-level zoom animations are not supported; can load AnnotationPages with many maps. — [@allmaps/leaflet](https://dev.allmaps.org/docs/packages/leaflet)
- Shared layer API (`@allmaps/warpedmaplayer`): options `opacity` (default 1), `removeColor` (default false), `projection`/`internalProjection` (WebMercator default); methods `getOpacity()`/`setOpacity()`, per-map selection and convex-hull helpers. — [@allmaps/warpedmaplayer](https://dev.allmaps.org/docs/packages/warpedmaplayer)
- Allmaps Tile Server: a Node proxy that turns Georeference Annotations into XYZ tiles for QGIS or any `L.tileLayer`; Allmaps CLI can export a GeoTIFF. — [Allmaps](https://allmaps.org); [Observable: Allmaps Tile Server](https://observablehq.com/@allmaps/allmaps-tile-server); [UWM Lesson 5](https://uwm-libraries.github.io/allmaps-intro-workshop)
- A worked Leaflet example used a transparency slider plugin alongside the Allmaps layer. — [Larsen tutorial](https://kristinalivlarsen.com/blog/georeferencing-IIIF-to-leaflet-tutorial)
- IIIF training uses a Library of Congress map manifest as the Allmaps example input, confirming LoC manifests work in the editor. — [IIIF training: Allmaps](https://training.iiif.io/annotations/use_cases/allmaps.html)

- UBC holds 285 digitised Tokugawa-period maps (zoomable). — [Duke LibGuide](https://guides.library.duke.edu/c.php?g=289731&p=1934061)

**OpenHistoricalMap as a historical basemap**
- Vector tiles: `https://vtiles.openhistoricalmap.org/maps/ohm/{z}/{x}/{y}.pbf` (plus `ohm_admin`, `osm_land`, `ne`); TileJSON at `/maps/{tileset}.json`; four styles including **Japanese Scroll** (`…/map-styles/japanese_scroll/ohm-japanese-scroll-map.json`) and **Woodblock** (`…/map-styles/woodblock/woodblock.json`); data is CC0, credit is "a courtesy"; no rate limits documented. — [OSM wiki: OpenHistoricalMap/Reuse](https://wiki.openstreetmap.org/wiki/OpenHistoricalMap/Reuse)
- `@openhistoricalmap/maplibre-gl-dates` (CC0-1.0) adds `map.filterByDate(date)` accepting `YYYY`, `YYYY-MM`, `YYYY-MM-DD` or Date (negative years OK); tiles need `start_date/end_date` or `start_decdate/end_decdate` (decimal years preferred for performance; 1.0 = 1 CE). — [maplibre-gl-dates](https://github.com/OpenHistoricalMap/maplibre-gl-dates/)

**3D terrain for Fuji/Hakone (free DEM)**
- AWS Terrain Tiles (Mapzen/Tilezen) on S3 Open Data: `https://s3.amazonaws.com/elevation-tiles-prod/terrarium/{z}/{x}/{y}.png`, no key; use `type: 'raster-dem', encoding: 'terrarium'`; attribution is source-dependent per Tilezen's attribution doc. — [Made with MapLibre](https://madewithmaplibre.com/basemaps/styles/aws-terrarium/); [AWS Open Data registry](https://registry.opendata.aws/terrain-tiles/)
- MapLibre 3D terrain example: separate raster-dem sources for terrain and hillshade "to improve render quality"; `terrain: {exaggeration: 1}`, hillshade `hillshade-shadow-color: '#473B24'`, `pitch: 70`, `maxPitch: 85`, `sky: {}`, `TerrainControl`. — [MapLibre 3D Terrain](https://maplibre.org/maplibre-gl-js/docs/examples/3d-terrain/)
- Practitioner guidance: pitch 30–70° to show relief, zoom 10–15, exaggeration ~1.2–1.5 for dramatic terrain, 0.5 for subtle. — [leafmap set_terrain](https://leafmap.org/maplibre/set_terrain/)

**Pacific-centred, dateline-safe projections**
- d3: `d3.geoNaturalEarth1().rotate([200, 0])` (equivalently −160) centres the Pacific; d3 performs antimeridian cutting during projection so rotated aspects render cleanly; pre-cut inputs should be run through `d3.geoStitch`/`geostitch` first. — [mapbox-gl-js issue 12010](https://github.com/mapbox/mapbox-gl-js/issues/12010); [d3-geo-projection](https://github.com/d3/d3-geo-projection); [Observable antimeridian cutting](https://observablehq.com/notebook-kit/ex/d3/antimeridian-cutting)
- d3 projection API: `clipAngle(null)` switches to antimeridian cutting; `fitExtent`/`fitSize` ignore clipExtent; `precision` governs adaptive resampling. — [d3-geo projections](https://d3js.org/d3-geo/projection)
- Mapbox GL's `naturalEarth` projection cannot be recentred on the Pacific (issue closed as duplicate). MapLibre offers `setProjection` and globe rendering (globe examples exist; `ProjectionData.clipAntimeridian` flag). — [mapbox-gl-js issue 12010](https://github.com/mapbox/mapbox-gl-js/issues/12010); [MapLibre globe example](https://www.maplibre.org/maplibre-gl-js/docs/examples/display-a-globe-with-a-vector-map); [ProjectionData](https://www.maplibre.org/maplibre-gl-js/docs/API/type-aliases/ProjectionData)
- Great-circle arcs crossing the antimeridian must be cut at ±180° or interpolated spherically to avoid wrap-around lines. — [Adaptive Composite Map Projections in D3 (paper)](https://sukolsak.com/files/cs448b_final_paper.pdf)
- World TopoJSON: `world-atlas` provides `land-110m`, `countries-110m`, `land-50m`, `countries-50m` (quantized, unprojected). Natural Earth source zips: 110m countries 210 KB, 50m countries 782 KB. — [topojson/world-atlas](https://github.com/topojson/world-atlas); [NE 110m](https://www.naturalearthdata.com/downloads/110m-cultural-vectors/110m-admin-0-countries); [NE 50m](https://www.naturalearthdata.com/downloads/50m-cultural-vectors/50m-admin-0-countries-2)

### Inferences
- Concrete Edo workflow: (1) take the Digital Commonwealth 1859 manifest (or LoC `tile.loc.gov` identifier / NDL kiriezu manifest), (2) georeference in Allmaps with ≥6 GCPs on bridges, castle gates and river mouths (kiriezu are schematic, so expect warping; a per-sheet mask is essential), (3) load the annotation in `@allmaps/maplibre` on top of OHM "Woodblock" or "Japanese Scroll" style filtered to 1859 via `filterByDate('1859')`, (4) bind a `<input type=range>` to `warpedMapLayer.setOpacity()`, (5) place pins from CODH's Edo Maps place-name dataset (GeoLOD IDs) as a GeoJSON symbol layer with `symbol-sort-key` priority. Because the Allmaps MapLibre plugin needs `maxPitch: 0`, the Fuji/Hakone 3D terrain scene must be a separate map instance or chapter.
- For the world map in d3, rotate a Natural Earth/Equal Earth projection by ~−150° to −160° and let d3 cut the antimeridian; for MapLibre, prefer globe view over trying to recentre a pseudocylindrical projection.

## KQ4 — How award-level projects treat portraits of historical figures and deep-zoom objects (crops, duotone, hover, provenance)

### Takeaway
Primary documentation of newsroom portrait treatments (duotone, cut-outs) was thin; the strongest concrete evidence is museum-side: uniform clipping (Faces of Sweden clips the bottom 8% of every image), consistent sampling density, lightbox-to-record links, and audio/image/related-object popovers (Museum of the World). For deep-zoom, OpenSeadragon (New BSD) is the IIIF engine under Mirador/Universal Viewer; provenance lines should follow the TASL pattern (Title, Author, Source, License) and institutional rights statements (e.g., Public Domain Mark; NDL requires 出典の記載).

### Cited Findings
- Faces of Sweden: all 785 portraits are date-ordered and chunked by century; uniform `clip-path: inset(0 0 8% 0)` hides catalogue numbers; thumbnails positioned by date centre; lightbox (PhotoSwipe) links out to the DigitaltMuseum record. — [Faces of Sweden](https://github.laiyagushi.com/riksantikvarieambetet/Faces-of-Sweden)
- Museum of the World object popover: image, identification, cultural affiliation, "Find out More" → description text + audio reading, Google map of locale, related objects; dots connect to related dots on click. — [Internet Archaeology review](https://intarch.ac.uk/journal/issue44/13/index.html)
- Google Arts & Culture lineage: "Museum View" (Street-View-like) and "Zoom Views" (high-res) sit alongside the timeline in the BM collaboration. — [Internet Archaeology review](https://intarch.ac.uk/journal/issue44/13/index.html)
- OpenSeadragon: "released under the New BSD license"; IIIF tile source accepts an `info.json` (example tiles `width 1024`, scaleFactors 1–32); supports `sequenceMode` for multi-image sets; needs CORS on the image server. — [OpenSeadragon](https://openseadragon.github.io); [IIIF tile source example](https://openseadragon.github.io/examples/tilesource-iiif)
- Mirador: open-source multi-window IIIF viewer (Image/Presentation v2 and v3, annotations, light/dark themes, 12 languages, RTL); Universal Viewer, Tify, Diva.js are alternatives; OpenSeadragon "is not embeddable" as a hosted viewer but is the engine others embed. — [IIIF viewers](https://iiif.io/get-started/iiif-viewers); [Project Mirador](https://projectmirador.org)
- Performance trap: Mirador via a manifest can double-request tiles (redirect per tile) vs. OpenSeadragon hitting the image service directly; and may request non-existent edge tiles. — [Omeka forum report](https://forum.omeka.org/t/accessing-big-images-through-iiif-manifests-is-extremely-slow/17175)
- IIIF cookbook `navPlace` recipe: a Manifest can carry GeoJSON-LD so a viewer can plot the object on a web map — a standards-based way to link deep-zoom objects to the map. — [IIIF Cookbook 0154](https://iiif.io/api/cookbook/recipe/0154-geo-extension)
- Image comparison ("peel the layers") components: `@cloudfour/image-compare` is a zero-dependency web component using a native `<input type=range>` so it is keyboard/AT operable; `img-comparison-slider` (sneas) supports React/Vue/Angular and ships a LICENSE file; Knight Lab JuxtaposeJS offers hosted authoring. — [Image Compare](https://image-compare-component.netlify.app); [img-comparison-slider](https://github.com/sneas/img-comparison-slider); [JuxtaposeJS how-to](https://annenbergdl.org/create-a-side-by-side-picture-comparison-with-juxtapose-js)
- 3D object viewers: `<model-viewer>` is "Licensed under the Apache License 2.0" (©2018–2025 Google), supports the last two versions of evergreen browsers and Safari, uses Intersection Observer to save GPU when off-screen, and a `poster` image to match the first render. — [modelviewer.dev](https://modelviewer.dev); [web.dev](https://web.dev/articles/model-viewer). Smithsonian Voyager is an "Open source 3D explorer and authoring tool suite" (Explorer web component + Story for annotations, articles, tours). — [Voyager docs](https://smithsonian.github.io/dpo-voyager)
- 2.5D depth parallax: pipeline = source image + greyscale depth map + WebGL displacement; depth maps from Depth Anything V2/V3 (HF Spaces, or `transformers` pipeline `depth-anything/Depth-Anything-V2-Large-hf`), or in-browser via Transformers.js/WebGPU; core fragment shader samples depth then offsets the colour UV by `u_offset * depth * u_strength`; smooth input with exponential lerp (`SMOOTHING ≈ 0.08`); cap `devicePixelRatio` at 2; the depth map may be half-resolution as long as aspect ratio matches. — [Sygnal KB: 2.5D parallax](https://www.sygnal.com/kb/image-25d-parallax-effects); [Codrops fake-3D](https://tympanus.net/codrops/2019/02/20/how-to-create-a-fake-3d-image-effect-with-webgl/)
- Shader approach beats CSS layered parallax because layers need manual cut-outs and show seams. — [Sygnal KB](https://www.sygnal.com/kb/image-25d-parallax-effects); three.js `displacementMap` on a PlaneGeometry gives a low-res result unless a custom ShaderMaterial is used. — [Stack Overflow](https://stackoverflow.com/questions/53537234/parallax-effect-using-three-js)
- Attribution convention: Creative Commons recommends TASL — Title, Author, Source, License — and recommends attribution even for public-domain works "when it is reasonable to do so". — [CC Best practices for attribution (archived)](https://web.archive.org/web/20230331185713/http://wiki.creativecommons.org/Best_practices_for_attribution)
- NDL Image Bank: all images out of copyright, commercial reuse allowed without application, but "出典の記載をお願いいたします" (please state the source). — [NDL Image Bank](https://www.ndl.go.jp/imagebank/about)
- Rights language seen on Edo map records: "Public Domain/No known restrictions on use. Contact host institution to download image." (Digital Commonwealth) — [Leventhal record](https://collections.leventhalmap.org/search/commonwealth:kh04p664d)

### Inferences
- A defensible portrait system for the unit: fixed aspect (e.g., 3:4) crops anchored on the eyes, uniform edge clipping to hide catalogue marks (as Faces of Sweden does), optional single-hue duotone only as a hover/inactive state so original colours remain available, and a provenance line in TASL order under every image ("Title, maker, holding institution, rights/licence, link").
- Deep-zoom prints should use OpenSeadragon directly against IIIF `info.json` (not via Mirador manifests) to avoid the double-request penalty, with `navPlace`-style geo links to drop a pin on the Edo map.

### Gaps
- No NYT/Pudding/Reuters/Guardian process post describing their portrait crop/duotone rules was found; the "duotone cut-out" convention remains an inference.
- Licence of `img-comparison-slider` and of JuxtaposeJS was not read from their LICENSE files; Smithsonian Voyager's exact licence text was not confirmed on the fetched page.

## KQ5 — Which open-source libraries (with licence) are the current best choices for each piece, and which are traps?

**Accessibility (maps/timelines)**
- "the accessible form of a picture of data is the data itself, as text": build the list/table first and wire the map to it; `Show on map` buttons; every marker needs a unique accessible name; announce result-count changes with a live region; iframe maps need a `title`. — [Accessibility.build guide](https://accessibility.build/guides/accessible-maps)
- WCAG mapping: 1.1.1 (data must exist as text), 2.1.1 (keyboard pan/zoom or equivalent list), 1.4.10 reflow at 320 px (tile text can't reflow), 2.5.7 dragging needs single-pointer alternative (visible pan/zoom buttons). — [Accessibility.build](https://accessibility.build/guides/accessible-maps)
- Avoid `role="application"` on maps unless full keyboard operation is built and tested; don't make every marker a Tab stop; don't capture page arrow keys unless the viewport has focus; provide an explicit "Use interactive map" action so embedded maps don't trap scrolling on small screens; canvas pixels have no semantics, so DOM alternatives are required; Leaflet makes the container and markers keyboard-operable by default. — [Maps Accessibility Best Practices (mgifford)](https://mgifford.github.io/ACCESSIBILITY.md/examples/MAPS_ACCESSIBILITY_BEST_PRACTICES.html)

- W3C Maps workshop position paper: non-visual maps require every feature to carry a `name`; raster maps and point-labelled extended features are "extremely difficult to make accessible". — [Biggs, W3C 2020 maps workshop](https://www.w3.org/2020/maps/supporting-material-uploads/position-statements/Brandon_Biggs-Smith-Kettlewell.pdf)

### Inferences
- Recommended stack map for the Edo unit: world map = d3 (ISC) + world-atlas 110m (50m only for the Japan inset); city map = MapLibre + Allmaps + OHM Woodblock/Japanese Scroll + maplibre-gl-dates; terrain = MapLibre terrain with AWS Terrarium; deep zoom = OpenSeadragon against IIIF info.json; comparison sliders = `@cloudfour/image-compare` (native range input → accessible by default); 3D = model-viewer; narrated sequences = Motion Canvas rendered to video, embedded with reduced-motion-aware autoplay; scroll choreography = Scrollama (tiny, MIT) with GSAP ScrollTrigger only where scrubbed timelines are needed.
